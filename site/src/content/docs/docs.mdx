Agent Rewake picks your Zed agent threads back up **when a usage limit resets**, so the work continues while you're away. It can also send a message into a thread later, once or on a repeat. It runs on your machine, in the threads you already have; there's no new agent to pick.

## Is it for you?

Rewake works in **Zed's Agent Panel** (⌘? on macOS, Ctrl+? on Linux, Ctrl+Shift+/ on Windows), with an **external agent** such as Claude Agent, Codex or Gemini CLI. If that's where you chat with your agent, it's for you.

It can't reach:

- **Zed's own agent** (the panel's built-in one): Zed doesn't let add-ons into it. Start the thread with Claude Agent in the same panel instead.
- **Claude outside the Agent Panel**: the Claude desktop app, claude.ai, or Claude Code in a terminal (Zed's included). Claude Code and the desktop app each have their own setting to continue after a usage limit.

## Install

You need Zed 1.22 or newer with its AI features on, an external agent in the Agent Panel (for example Claude Agent, signed in; `install` can add it for you) and Node.js 22 or newer. It works on macOS, Linux and Windows.

```sh
npx @codizelabs/agent-rewake install
```

`install` lists the agents it will add Rewake to and asks before writing anything. Rewake goes in front of each agent under the agent's own name, so your existing threads keep working. Each file is backed up first; comments and settings are kept.

**Then quit Zed completely and open it again** (⌘Q on macOS, Ctrl+Q on Linux; on Windows, close every Zed window), open the **Agent Panel**, and open or start a thread with one of your agents. Zed starts Rewake with that thread, not when Zed itself starts. `npx @codizelabs/agent-rewake doctor` confirms it: "Working: Zed last started it …".

The commands below are written as `agent-rewake …`; run them with `npx @codizelabs/agent-rewake …`, or install it once with `npm install -g @codizelabs/agent-rewake`.

A **Rewake** menu now appears under the message box, next to the model picker.

## Resume after a usage limit

When an agent stops at its usage limit, Rewake adds a form to the thread with your resume message, ready to edit.

<ResumeScene />

- **Submit** sends the message about a minute after the limit resets. If the agent is still limited then, Rewake waits for the new reset time and tries again.
- **Decline** schedules nothing.
- If the agent doesn't say when the limit resets (Gemini CLI, for example), the form asks when: in 30 minutes, 1, 3 or 5 hours, or a custom time.

**More work after the resume:** while a resume is scheduled, **Rewake → Add a message after the resume…** queues follow-ups (up to 20). Each goes when the reply before it finishes.

**Change the resume message** in the form, or with `/schedule prompt <text>`. If you continue the thread yourself after the reset, the pending resume is cancelled.

### Make it automatic

When you open a new thread, Rewake asks once whether to resume it automatically. Choose *every new thread*, *this thread only*, or *don't ask again*. For a thread that's already open, use **Rewake → Turn on auto-resume after limits…** (or `/schedule auto on`).

Automatic resume asks you instead of sending when:

- with Claude, your Claude setting "Continue automatically at usage limit" is off;
- the limit resets more than 24 hours from now (a weekly limit, for example);
- you chose *On, except when permissions are bypassed* in **Settings…** and the thread skips permission prompts;
- the agent gave the same reset time as last time, or never says when it resets and the limit has lasted about a day.

Credit, spend and billing limits are never resumed: waiting doesn't fix them, and Rewake says so in the thread. If the message gives a reset time, even next to an offer of credits ("buy more credits, or try again at 2:51 PM"), the limit resets, and Rewake resumes the thread then. Rewake never approves permission requests; those wait for you in Zed.

## Schedule a message

**Rewake → Schedule a message…**: type the message, pick a time (in 30 minutes, 1 or 3 hours, tomorrow morning, when the usage limit resets, or a custom time), and press **Submit**. Or type it:

```text
/schedule 09:00 Check the build
/schedule in 3h Run the tests
/schedule every weekday 09:00 Summarise yesterday's commits
```

To repeat on any schedule, pick **Custom time…** and type a cron expression such as `0 9 * * 1-5`; Rewake shows what it understood and the next runs before saving.

You can also ask the agent ("check the CI run again in 30 minutes"). It proposes the message, and you approve or edit it in the thread.

**When it's sent:** the message appears in the thread as yours and the agent replies there. If the agent is busy, it waits for the reply to finish. If Zed or your computer wasn't running and it's more than 15 minutes late, it's marked **Missed** and Rewake asks whether to send it now.

## See and change scheduled messages

- **Rewake → Schedules** shows this thread's messages.
- **Rewake → Change a scheduled message…** changes the time or text, sends it now, pauses or deletes it.
- **Every thread at once:** run the Zed task **Agent Rewake: schedules** (command palette → *task: spawn*), or `agent-rewake ui` in any terminal. Add `--keybinding` to `install` for ⌘⌥R (Ctrl+Alt+R elsewhere; on Windows, Ctrl+Alt can be AltGr, so change it in Zed's `keymap.json` if it types a character).

## Settings

**Rewake → Settings…** applies to every thread:

- **Automatic resume after usage limits:** *Ask when a new thread opens* (default), *On, except when permissions are bypassed*, *On, even when permissions are bypassed*, or *Off*. "On" also covers threads Rewake sees for the first time, such as ones you reopen after installing it.
- **Time format:** 12-hour (default) or 24-hour.
- **Keep this computer awake for resumes and scheduled messages** (macOS): *While it's plugged in* (default), *Always, also on battery* or *Never*. While a resume or scheduled message is due within six hours, or while the agent is working on a scheduled message, Rewake stops the computer from idling to sleep, and says so once in the thread. Closing the lid, choosing Sleep or a flat battery still put it to sleep, and Rewake can't wake a sleeping computer. On Linux and Windows this setting isn't offered yet.

## Agents

Rewake works the same way in front of every external agent Zed runs: Claude Agent, Codex, Gemini CLI, GitHub Copilot, OpenCode, goose and the rest. Rewake knows how each of them reports a limit: an error, its own error codes, or a last line such as Cursor's "Upgrade your plan to continue". When the agent says when the limit resets, Rewake resumes at that time; otherwise it asks you when. Zed's own agent isn't an external agent, so Rewake can't be added to it.

### Outside Zed: previews

To continue a Claude Code, Codex or other agent session after a usage limit outside Zed, in a terminal or the Claude desktop app, install a preview. Previews aren't installed by default, haven't been checked with every account type yet, and may change.

| Agent | Install | How to use it |
|---|---|---|
| Claude Code (terminal, and the Claude desktop app's Code tab) | `npx @codizelabs/agent-rewake install --only claude-code` | At a usage limit, Rewake offers to continue the session after the reset. Keep Claude Code open. |
| Codex (terminal) | `npx @codizelabs/agent-rewake install --only codex` | Trust Rewake's hooks in Codex once ("Hooks need review"). At a usage limit, type `rewake` in the thread; Rewake continues the thread after the reset. |
| GitHub Copilot CLI, Grok Build, Gemini CLI, Antigravity CLI | `npx @codizelabs/agent-rewake install --only copilot-cli` (or `grok`, `gemini-cli`, `antigravity`) | Once the session is closed, run `npx @codizelabs/agent-rewake continue`; run it any time before the reset, and Rewake waits until then. Run `continue --always` once, and from then on Rewake continues closed sessions by itself when the reset is within a day. |

For every preview, keep the computer on and awake until the time Rewake gives. On macOS the Claude Code preview keeps it from idling to sleep while a continue is due within six hours, and every preview does while the agent works on the resumed session (the **Keep this computer awake** setting decides). `install` and `doctor` list the previews you set up.

In Claude Code, `/rewake-schedule` also schedules a message into the session. To remove a preview: `npx @codizelabs/agent-rewake uninstall --only <name>`.

## Privacy and security

- Everything runs on your machine. Rewake makes no network calls of its own and never sees your credentials; sign-in goes through the agent's own flow.
- It sends only what you scheduled, what you approved, or the resume message you turned on.
- It stores scheduled messages, per-thread settings and metadata-only logs (never message content) in its state directory, with owner-only permissions. `doctor --details` prints where. Plain `doctor` names no folders, accounts or keys, so you can paste its output anywhere.
- Anything it sends runs with your account and the thread's permission settings while you may be away. Report vulnerabilities privately: [SECURITY.md](https://github.com/codizelabs/agent-rewake/blob/main/SECURITY.md).

## Troubleshooting

Start with `agent-rewake doctor`. It checks Zed (installed, version, AI features on), your agents and which have Rewake, whether Zed has started it, the version and Node.js Zed uses, settings that override Rewake's, sign-in, your scheduled messages and recent start failures, and gives the fix for each. It works offline and prints no folders, accounts or keys (`--details` adds versions and folders for bug reports). In Zed, `dev: open acp logs` shows the agent connection. Then [open an issue](https://github.com/codizelabs/agent-rewake/issues/new/choose).

- **Installed, but nothing happens (`doctor` says "Not used yet"):** Zed starts Rewake only when you open or start a thread with a Rewake agent in the **Agent Panel**; restarting Zed isn't enough. If you chat with Claude in the Claude desktop app, claude.ai or a terminal, Rewake can't reach it there: see [Is it for you?](#is-it-for-you). To remove it: `agent-rewake uninstall`.
- **No Rewake menu, or `/schedule` goes to the agent:** quit Zed completely and reopen it after `install`. Check that `install` listed the agent you use. For agents without their own toolbar options, type `/schedule`: it opens the same forms.
- **Will it send while Zed is closed?** No: Rewake runs inside Zed. After a restart, open the thread once. Late messages ask before sending.
- **The resume form didn't appear:** it appears only for limits that a wait fixes. Use **Rewake → Resume after the usage limit…** or `/schedule resume`.
- **The thread stopped responding after a limit:** a known Zed issue ([#55501](https://github.com/zed-industries/zed/issues/55501)). Rewake reconnects a thread whose session the agent lost; without Rewake, reload the agent in Zed.
- **"Another Zed window owns this thread":** the thread is open in two windows; only one sends.

## Update

The same two steps for every version, from any earlier one:

1. Run the install command again, with `@latest`:

   ```sh
   npx @codizelabs/agent-rewake@latest install
   ```

   It shows which agents it updates, and from which version to which, and asks first.
2. **Quit Zed completely and open it again** (⌘Q on macOS, Ctrl+Q on Linux; on Windows, close every Zed window). Zed keeps agents it already started on the old version until then.

Your threads, scheduled messages, automatic-resume choices and settings stay as they are: they live in Rewake's own folder, which an update doesn't touch. A message due while Zed is closed for the restart is sent when you reopen its thread, or, if it's more than 15 minutes late, Rewake asks first (a repeating message skips to its next run).

Check it with `npx @codizelabs/agent-rewake@latest doctor`. It says if Zed still starts an older version, and what to do.

- **Why run install again:** `install` writes the exact version into Zed's settings, so Zed keeps the version you installed until you run it again. Updates never happen behind your back.
- **Why `@latest`:** `npx @codizelabs/agent-rewake install` without it may run a copy npx saved earlier.
- **Installed with `npm install -g`:** run `npm install -g @codizelabs/agent-rewake@latest`, then `agent-rewake install`, then restart Zed.
- **After you upgrade or move Node.js:** run the install command again too, so Zed's settings point at the new Node.js. `doctor` tells you when that's needed.
- **Going back to an earlier version:** run that version's install, for example `npx @codizelabs/agent-rewake@0.1.1 install`, and restart Zed.

### Version-specific steps

None so far: every version updates with the two steps above. If a release ever needs anything more (a newer Node.js or Zed, a setting renamed, stored messages in a new format), it's listed here and under **Upgrade notes** for that version in the [CHANGELOG](https://github.com/codizelabs/agent-rewake/blob/main/CHANGELOG.md), and `doctor` checks for it where it can.

| From | To | Extra steps |
|---|---|---|
| Any earlier version | Any later version | None |

## Uninstall

`agent-rewake uninstall` puts every agent back the way it was and removes Rewake's task and keybinding, after showing you the list. Then delete Rewake's folder, which `agent-rewake doctor --details` shows. Pending messages aren't sent after removal.

| Command | What it does |
|---|---|
| `/schedule` | Open the "Schedule a message" form |

| `/schedule list` | This thread's scheduled messages |
| `/schedule rm N`, `/schedule now N`, `/schedule pause N`, `/schedule resume N` | Delete, send now, pause, or resume a paused message |
| `/schedule move N <when>`, `/schedule edit N <text>` | Change the time or the text |
| `/schedule resume` | Schedule the resume message after the current usage limit |
| `/schedule auto on`, `/schedule auto off` | Automatic resume for this thread |
| `/schedule prompt <text>` | Set this thread's resume message |
| `/schedule page` | Open an overview of every scheduled message |
| `/stop` | Stop a scheduled reply that is running |

<details>
<summary>Scheduled-message states</summary>

| State | Meaning |
|---|---|
| Scheduled | Waiting for its time |
| Paused | Kept, not sent until resumed |
| Queued | Due, waiting for the agent's current reply |
| Sending | Sent; reply in progress |
| Sent | The agent replied |
| Failed | The agent returned an error |
| Missed | Due while Zed or the computer wasn't running |
| Stopped | Stopped with `/stop` |
| Cancelled | Cancelled, for example because you continued by hand |
| Needs you | Waiting for you to confirm, for example a reset more than a day away |
| Waiting for limit | Reserved; a resume waiting for its reset shows as *Scheduled* |

</details>

<details>
<summary>Environment variables</summary>

| Variable | Effect |
|---|---|
| `AGENT_REWAKE_STATE_DIR` | Where schedules and settings are stored (default: macOS `~/Library/Application Support/agent-rewake`, Linux `~/.local/state/agent-rewake`, Windows `%LOCALAPPDATA%\agent-rewake`) |
| `AGENT_REWAKE_ZED_CONFIG_DIR` | Which Zed settings `install` edits (default: where Zed keeps them, including a Flatpak Zed's) |
| `AGENT_REWAKE_ZED_DATA_DIR` | Where Zed keeps its registry cache and installed agents |
| `AGENT_REWAKE_ALLOW_AUTO=0` | Turn off automatic resume everywhere |
| `AGENT_REWAKE_AGENT_TOOLS=0` | Don't give the agent Rewake's tools |
| `AGENT_REWAKE_KEEP_API_KEY=1` | Pass `ANTHROPIC_API_KEY` to the Claude adapter instead of blanking it |
| `AGENT_REWAKE_TITLE_MARKERS=1` | Add markers such as `Scheduled 09:00 ·` to thread titles |
| `AGENT_REWAKE_PLATFORM` | Which build of a binary agent to run (testing) |
| `AGENT_REWAKE_LINK` | Internal: links the agent's tool server to its thread |
| `AGENT_REWAKE_OWNER` | Internal: set by Rewake on the agents it runs in Zed, so they're never resumed twice |
| `AGENT_REWAKE_FIRE` | Internal: set by Rewake on an agent it starts to continue a session, so that run isn't taken for you typing |

</details>
