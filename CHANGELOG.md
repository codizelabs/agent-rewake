# Changelog

All notable changes to Agent Rewake are documented here. The format follows [Keep a Changelog](https://keepachangelog.com/en/1.1.0/), and the project uses [Semantic Versioning](https://semver.org/spec/v2.0.0.html). While the version is `0.x`, a minor release may contain breaking changes, always called out below.

## [Unreleased]

### Added

- **Keeping the computer awake while a resume is due now also works on Linux and Windows:** on Linux with systemd Rewake uses `systemd-inhibit`, on Windows a hidden PowerShell holding the system awake, both tied to Rewake's process so they end with it, and "while plugged in" is honoured on both. Only macOS has been tried by hand. The Claude Code preview's own hold is still macOS only.
- **`agent-rewake doctor` checks that the hooks and timers can still run:** it says when Rewake's helper file or its Node.js finder is missing, when no Node.js 22 or newer can be found, and, as a note, when an agent is set up but Rewake has never seen it run, each with the command that fixes it.
- **Timers for resumes that no longer exist are removed:** any Rewake command now clears leftover timers of resumes that were cancelled, finished or deleted.
- **A Claude Code session you closed at its usage limit can now be continued (macOS, Linux; preview):** if you close Claude Code (or it quits, or the computer restarts) before Rewake's question was answered, `agent-rewake continue` lists the session, and at the reset a system timer continues that same session in the background with Claude Code's own `claude --resume <session id> -p`, with your message on standard input. It never skips permission prompts (a step that would need your approval is denied), never uses `--continue`, and runs in the session's folder with the settings it had (`CLAUDE_CONFIG_DIR`, a gateway address; never an API key). It doesn't continue if you typed in the session after the limit, if the session is open again, or if its transcript changed after the limit: in that last case a notification says so. This was tried only against a stand-in `claude` program, not yet against a real usage limit; the docs say so.
- **`agent-rewake schedules --explain <id>` says what will happen:** for one planned resume or message, in plain words, what Rewake will do at its time and what could stop it (you typing in the session, the agent continuing by itself, the session being open, a later usage limit, the computer being off). It sends nothing and changes nothing. The id is the eight characters in square brackets in `agent-rewake schedules`.
- **Rewake's settings outside Zed: `agent-rewake settings`:** lists every setting with its value and what it does. `agent-rewake settings change` lets you pick one and its new value by number, `agent-rewake settings <name> <value>` changes one (for example `agent-rewake settings clock 24h`) and `agent-rewake settings --reset <name>` puts it back. They are the same settings as Zed's **Rewake → Settings…**, checked the same way: `new-threads`, `auto-when-prompts-skipped`, `clock`, `keep-awake` (only where Rewake can keep the computer awake) and `resume-prompt`. Shell completion knows the names.
- **Cancel one planned resume outside Zed:** with several planned, `agent-rewake continue --cancel` in a terminal lists them to pick one, or all, and `agent-rewake continue --cancel <id>` cancels one by the eight characters in square brackets in `agent-rewake schedules`, Codex resumes too. A resume that is already running isn't cancelled, and Rewake says so.
- **`agent-rewake schedules` marks the resumes outside Zed:** each is marked `[outside Zed]`, named after its agent, and called what that agent calls it (a session, a Codex thread, a Cursor chat), and the list ends with how to cancel one. The schedules page uses the same words, and `schedules --explain` names the command that cancels that one resume.
- **`agent-rewake continue` tells you when a session is large:** where the agent gives Rewake the path of its history file (Gemini CLI and Cursor), a history of 5 MB or more adds "This session is large (about N MB of history); continuing it re-reads that and uses your plan." Only the file's size is looked at, never what's in it, and nothing is paused.

### Changed

- **Third-party facts on the website carry the date they were checked:** the Claude, Codex and Gemini limit facts were re-read at their sources on 9 October 2026, and the Codex five-hour period is now stated as Plus and Standard Business only (Pro has none); the Gemini line says which accounts moved to Antigravity CLI and when.
- **The README and docs say what the code does:** Cursor's own agent is named with the other places, the README says the data folder is shown by `doctor --details` (not plain `doctor`), the `/rewake cancel` command is described for the agents that have it, and the note about newer agent versions names which agents `doctor` compares.
- **The website says more about what Rewake does and doesn't do.** The landing page has a table of what works where, with each place's status and what must stay open; a list of what Rewake will never do; safety questions in the comparison; the commands to install one place only, with their real `--only` names; the night-to-morning story in words; and answers to more questions (Claude Code's own continue, sleeping computers, how to tell it worked, missing a limit). There is a page for [privacy and security](https://codizelabs.github.io/agent-rewake/docs/privacy-and-security/), a [changelog](https://codizelabs.github.io/agent-rewake/changelog/) built from this file (released versions only), and a section on how to report a limit Rewake missed. Each page now has its own title and description when you share its link.
- **Help for every command:** `agent-rewake install --help`, `doctor --help` and the other commands each show their own options (before, `install --help` failed and `doctor --help` ran the check). The main help lists the commands you run first, with `cursor` among the places and `uninstall`'s `--only`, `--all` and `--skip`; the commands Rewake starts itself are left out of it and listed by `--help --all`. `agent-rewake completion bash`, `zsh` or `fish` prints a completion script; nothing is installed for you.
- **`agent-rewake history [--days 7]`:** what happened to your scheduled messages and resumes, newest first, with the agent and folder and what happened and why (sent, cancelled because you typed, too late, still limited, failed and the reason), and the year in each date. `schedules --all` now names the agent, lists newest first and says how each one ended, with the year.
- **`agent-rewake doctor --report`:** writes one text file for a bug report, with the warnings and errors of the last 14 days, the timers set against the resumes on file, each agent's session states and the last decisions when a timer fired. Your home folder shows as `~`, session ids are replaced by hashes and message text, thread titles and folder names are left out. Rewake sends nothing, checks nothing online and doesn't open a browser: it prints where the file is and the link to open an issue yourself.
- **`agent-rewake doctor --json`:** the same findings as JSON, for scripts.
- **`doctor` says how old your installed version is:** "Rewake 0.3.1, installed 94 days ago. To update: npx @codizelabs/agent-rewake@latest install", from a note `install` keeps in Rewake's own folder. It never checks online. A Rewake installed before this version shows it after the next `install`.
- **`doctor` says each level in words** (`Problem:`, `To do:`, `Note:`, `OK:`) as well as with a symbol, and the schedules page's help names `agent-rewake schedules`, the plain-text list for screen readers.
- **A failed download of an agent says why it may have failed and what to do:** when Zed has no copy of an agent and Rewake downloads it, a proxy in your environment (`HTTPS_PROXY`, `HTTP_PROXY`, `NO_PROXY`) is now used on Node.js 24.14 or newer, and on 22.21 or newer when Zed is started with `NODE_USE_ENV_PROXY=1` (before, Node's own download ignored it). Agents installed with npm already got your proxy variables and npm settings. If it still fails, Rewake says it couldn't download the agent, whether a proxy was involved, and to open the agent once in Zed without Rewake. Tried against a local proxy only.
- **`agent-rewake doctor --limit-sample "<message>"` helps report a limit message Rewake missed.** Paste the message your agent showed. Rewake shows it with keys, email addresses and your home folder removed, says how each agent's rules read it (a usage limit and when it resets, a billing limit, a short wait, or not a limit), and prints a link to a pre-filled GitHub issue. It runs on your computer, reads none of Rewake's records, sends nothing and opens nothing: you open the link, read the form and submit it yourself.
- **The release checks keep what npm downloads with Rewake from growing:** a release now fails if Rewake would depend on any package other than the Claude adapter, if the adapter isn't pinned to one exact version, or if optional, peer or bundled dependencies are added. Nothing changes in what you install today.

### Fixed

- **Windows: a long resume is no longer cut off after an hour.** Windows' Task Scheduler stopped Rewake's timer task after one hour, though a resume may run for up to three hours before Rewake stops it itself. The task may now run for four hours.
- **Windows: stopping a resume stops everything the agent started.** When a resume ran past three hours, or you stopped it with `agent-rewake continue --cancel`, only the agent's own process was ended on Windows, so programs it had started could keep working on the session. Rewake now ends the whole process tree there (`taskkill /T`). macOS and Linux are unchanged.
- **Cursor on Windows:** a `hooks.json` saved with a byte-order mark (as Notepad or Windows PowerShell 5.1 may save it) is no longer refused as invalid, and Cursor's command is found on the `Path` of an environment Rewake copied.
- **Windows can tell whether an agent session is still open:** Rewake now finds the agent that ran a hook by walking up the process tree (through `cmd` and PowerShell), as it does on macOS and Linux, so a crashed or killed agent no longer leaves a resume blocked or double-sent. Tried only in automated tests so far, not by hand on a Windows PC.
- **Smaller hardening:** a binary agent is downloaded only over https, and its command path is checked before anything is moved; a session id can't start with a dash; Rewake closes its own state folders to other users if they were left open; the backups Rewake makes of your files never overwrite each other and only the newest five are kept; an address with a user name, password or query (often a key) isn't saved with a session, only that it was set.
- **A folder name with curly quotes can no longer break a Windows notification:** every quote character PowerShell treats as a quote is now escaped in the notification text.
- **Planned resumes no longer keep your API keys:** timers started through `at`, `systemd` or Rewake's own waiter now run with a cleaned environment, so keys from the session that planned them aren't saved on disk or used to skip the missing-key check.
- **Text from an agent can no longer send commands to your terminal through Rewake's lists:** thread titles, folder names and message text are shown with escape and other control characters replaced, in `agent-rewake schedules`, its Markdown snapshot and the schedules page.
- **Codex: a later, empty usage bucket no longer hides when the limit resets:** Codex reports usage per limit bucket, and an empty "premium" snapshot after a full "codex" one made Rewake say it didn't know when the limit resets. Rewake now picks the bucket that describes the limit, and falls back to the reset time in Codex's own message.
- **Codex: a crashed send can no longer be counted as sent because of an older resume:** after a second usage limit in the same thread, the first resume's identical message was still in the thread's file, so a send that crashed could be marked as sent. Rewake now counts only messages written after that attempt started.
- **Claude Code: a continue refused just after the reset is tried again:** when the first request after a reset was refused and no new reset time was given, nothing retried and the session stayed stopped. Rewake now tries again shortly, once. If that is refused too, it stops, as it does for a limit that keeps coming back.
- **`agent-rewake doctor` warns when Claude Code is set to keep retrying at a usage limit:** `CLAUDE_CODE_RETRY_WATCHDOG`, or `CLAUDE_CODE_MAX_RETRIES` of 10 or more, set in the environment Claude Code starts with or in the `env` section of its `settings.json`, may keep the turn from ending, so Rewake may never see the limit. Doctor names the variable and where it's set.
- **Gemini CLI: more usage limits are noticed, with their reset.** A quota error worded only "You exceeded your current quota…", "Resource has been exhausted…" or with Gemini's "request a quota increase through AI Studio" line wasn't recognised as a usage limit, so Rewake offered nothing. It is now. When Gemini says "Suggested retry after 3600s" or "Please retry in 1234s", Rewake waits for that time instead of asking you to pick one.
- **Gemini CLI: a limit hit during another extension's turn is noticed.** Turns started by another Gemini CLI extension (a loop extension such as Ralph, for one) were skipped, so a limit in them was never recorded. They are checked now.
- **Gemini CLI: Rewake no longer reports "sent" when Gemini refused a step.** A continued session runs without a terminal, so Gemini CLI refuses any edit or command that needs your approval and carries on. Rewake now notifies you that it refused a step that needs your approval, so the work may be unfinished, and says to open the session and approve it there. The Gemini CLI guide now says that a continued session can't ask for approval, and that you should choose **Stop** at Gemini CLI's usage-limit question, because Rewake can't see the limit while that question is open.
- **Copilot CLI: more of its limits are recognised.** Errors that carry the limit's code inside an `error` object (`{"error":{"code":"user_weekly_rate_limited"}}`) were missed, and so was the wording "Sorry, you have exceeded your weekly rate limit." Now `user_global_rate_limited` (the session limit), `user_model_rate_limited` and `integration_rate_limited` are limits too, a bare `rate_limited` is left to Copilot, and a code with a suffix (`…:pro`) is read by its first part. When a continued run hits the limit again, Rewake uses the number of seconds Copilot gives as the reset, and a quota error about money (`billing_not_configured`) is reported as a failure with Copilot's message, not retried at a reset.
- **Grok Build: a continued run that hits the limit again is waited out.** A free account's run prints "You've reached your free Grok Build usage limit…" with no "rate limit" or "429" in it, so Rewake called the run failed and didn't try again at the reset. And a 402 "Grok Build usage balance exhausted" (which Grok's own screen calls the weekly limit) was treated as billing unless Grok's log, within the last 30 minutes, said the usage was used up. It is now the weekly limit, and you choose the time when Rewake doesn't know it; a spending cap or credit limit is still billing.
- **Antigravity: more limit texts are read, and the CLI's errors aren't thrown away.** "Model quota limit exceeded" counts as a limit, and "Refreshes in 2h30m" and "Refreshes in 6 days and 18 hours" are read as the reset (before, only "Resets in …" was). When a continued run fails, Rewake now reads what `agy` prints on stderr (its `AGY_ERROR` line) as well, so a run that hits the quota again is waited out instead of reported as "no response". The Antigravity wordings come from Google's forum and a community tool, not from Google's documentation, and the CLI may not print all of them.
- **Removing or upgrading Node.js no longer stops your agents in Zed (macOS, Linux), and starting them no longer needs npm or the network:** Zed's agent entries named one Node.js folder and ran Rewake through npm each time, so `nvm uninstall`, an upgrade or an empty npm cache stopped every wrapped agent with an error that didn't mention Rewake. The entries for Codex and the other agents Rewake is in front of now start the same two files in Rewake's own folder that hooks and timers use (`bin/rewake-node` and `bin/agent-rewake.mjs`), which find a working Node.js themselves. **Run `npx @codizelabs/agent-rewake@latest install` once to move your Zed entries over**, then quit Zed completely and open it again; `doctor` now says when an entry still uses the old start. From then on, install or any newer Rewake that runs updates the copy Zed starts, and an older Rewake never replaces a newer one. `uninstall` puts your original entries back and leaves those two files, which hooks still use. Windows is unchanged: run install again after you upgrade Node.js there.
- **`doctor` and `install` now judge the same copy of an agent.** When an agent is installed twice (an npm copy and a native one, say), `doctor` went by the copy that runs first in your terminal and `install` by the newest, so `doctor` could call Claude Code 2.1.282 too old while 2.1.292 was installed. Both now use the copy your terminal starts, the first one on your PATH. `doctor --details` lists every copy with its version and says which one Rewake goes by. (If that first copy is too old, `install` says so and tells you to update it.)
- **A bug in Rewake can no longer end your agent's session in Zed.** Before, an error inside Rewake while it handled a message ended the whole process, and with it the agent and the reply you were waiting for. Now Rewake switches itself off in that agent, passes everything between Zed and the agent through untouched, tells you once in each thread, and logs the kind of error (never its text). Restart Zed to turn it back on; your scheduled messages are kept but aren't sent until then.
- **A project folder that was moved, renamed or deleted now gets a clear reason.** Resuming a closed Copilot CLI, Gemini CLI, Grok Build or Antigravity session from a folder that is gone said "Rewake couldn't continue the session" (or, for Gemini, that the session no longer exists). Rewake now checks the folder first, doesn't start the agent, and says the project folder is gone and to open the session from its new folder.
- **`agent-rewake uninstall` leaves nothing running behind:** once Rewake is out of every place, it also removes the timers, the login item and the helper files it made. Your scheduled messages, settings, logs and any agents Rewake downloaded stay, and it lists them with where they are.
- **Many sessions resuming at the same moment are spaced out:** resumes outside Zed that fall due together start a few seconds apart, and at most two run at once; the others wait their turn.
- **Rewake's folder no longer grows without end:** finished resumes and old session records older than 30 days, and leftover temporary files, are cleared. Anything pending or recent is never touched.
- **A clear message for Node.js older than 22:** instead of an error, Rewake says which Node.js it needs and what to do.
- **First-run advice starts from the places that are set up,** not from Zed.
- **A timer that ran too early no longer leaves a resume waiting for someone to open an agent:** after a time-zone change, or in the repeated hour when daylight saving ends, a timer could run before its time, do nothing, and be gone. It now sets a new one for the right moment (up to three times for one resume), and leaves it alone if the one that's there is still right.
- **Two Rewake processes no longer lose track of who owns a session when the computer's name changes, or when a process number is reused:** ownership was decided by the process number and the computer's name. macOS renames the computer with the network, so a running owner could look gone and a second process could take over (a message sent twice); a process number reused after a crash could keep a dead owner's lock alive. Ownership now follows the process's start time (where the system reports it) and ignores the computer's name.
- **Codex Business and Team: a workspace limit with a spent plan window is no longer treated as billing for ever.** When Codex says the workspace is out of credits or over its spend cap, and the five-hour or weekly window is used up too (99% or more) with a reset time still ahead, Rewake now offers to continue at that reset. It always asks first, even with automatic resume on, because only a community report (unsnooze 1.19.1 and 1.19.2) backs this and no Codex capture of it exists yet. A workspace limit with no spent window, or with a spend cap flag set, is still billing.
- **Claude's older "Your limit will reset at 3pm (UTC)" limit message is no longer dropped as a short wait (Zed).** Rewake now reads it as a usage limit, with the time.
- **Claude's "You've hit your monthly limit · resets Sep 1 at 12:00am" is no longer called billing (Zed).** It resets, so Rewake asks about it like any limit more than a day away. A monthly limit that gives no reset is still treated as billing.
- **Kimi's "Membership expired, please renew your plan" is now explained as a billing problem, and OpenCode's "Free usage exceeded, subscribe to Go" is now a usage limit (Zed):** before, Rewake did nothing for either. The OpenCode text gives no reset time, so Rewake asks you for one. Both texts are known only from the community project unsnooze, not from a capture by the agent.

## [0.3.1] - 2026-10-08

### Fixed

- **A scheduled message that meets a usage limit waits for the reset instead of failing.** Claude reports a spend cap as a billing error even when the message ends with the plan's own reset ("…your weekly limit resets Oct 13 at 6am"); Rewake read that as "waiting won't help", showed the error and stopped. It now holds the message until that reset, even days away, and says so in the thread. A scheduled message whose limit gives no reset time is tried again after the wait set in Settings (an hour unless changed), for up to a day, instead of asking.
- **A closed session Rewake continues is no longer invisible or cut short:** a notification now says when the background run starts (with how to stop it) and when it's done; `agent-rewake continue --cancel` offers to stop a running one; and a run may take up to three hours instead of being stopped after 30 minutes, mid-work.
- **Removing or upgrading Node.js no longer breaks Rewake's hooks and timers (macOS, Linux):** with nvm, fnm or asdf, every hook, timer and the login item named one versioned Node.js folder, so `nvm uninstall` made them all fail silently. They now run a small script in Rewake's folder (`bin/rewake-node`) that uses the Node.js Rewake was set up with while it exists, else finds another (Homebrew, Volta, fnm, asdf, nvm, the system, your PATH) and says so if there is none. The first time you run `install` again, the hook commands change once, so Codex asks you to trust its hooks again. Zed's own agent entries still name one Node.js; those are not covered yet.
- **Fewer secrets and personal details reach your screen and logs:** the agent error line `continue` shows now also hides `api_key=…`/`password=…` style values, AWS access keys, `Basic` and `Bearer` credentials, and strips every terminal escape sequence (such as clickable links), not only colours. Rewake's log records the agent's program name, not its full path (which holds your user name).
- **`agent-rewake continue --always` says where it applies:** it's one setting for every agent, so it also turns on automatic resume in new Zed threads and in Claude Code, not only for closed sessions. The message now names them, and says `--ask` turns it off everywhere.
- **A limit line an agent wrote itself no longer starts an unattended resume in a thread that skips permission prompts (Zed):** for agents that report a usage limit only as the last line of their reply (Cursor, Copilot, Amp, Droid, Antigravity), text a model was steered into writing could have made Rewake continue the thread later with nobody watching. In threads that bypass permission prompts, Rewake now asks first; elsewhere automatic resume works as before.
- **Cursor's own agent no longer offers a wait that can't work for a plan or monthly limit:** Cursor's Pro-plan limit ("Switch to Auto for more usage or set a Spend Limit") and its monthly-allowance line ("…reset when your monthly cycle ends on …") were treated like a limit that lifts within hours, so `agent-rewake continue` offered times that would only hit the limit again. They now get a notification instead.
- **Cancelling now always wins over a continue that hasn't started sending:** before, a cancel (or typing in the session) just as Rewake was about to send could be missed, and the message was sent anyway. A continue that is already sending can't be taken back, so `agent-rewake continue --cancel` now says "Not cancelled: Rewake is already continuing …" and how to see what it did, instead of "Cancelled".
- **`agent-rewake uninstall` takes Rewake out of every place it's set up in:** before, it removed only Zed's entries but said Rewake was gone everywhere. Now it shows every change first, asks once, and says what's left (Rewake's own folder). To keep some places, use `--only` or `--skip`.
- **Commands Rewake tells you to run now work when you installed with npx:** notifications, `continue`, `doctor`, install messages and the schedules page said "Run agent-rewake continue", which isn't a command unless Rewake is installed globally. When `agent-rewake` isn't on your PATH, they now say `npx @codizelabs/agent-rewake continue`, and the same for every other command.
- **Claims on the website that weren't true.** The comparison said community scripts poll a usage endpoint "until it rate-limits them in turn" (the tool that did this fixed it and closed both issues), that several of the most-starred are "stale or archived" (none of the six most-starred is archived; they are stale), and that one "presses Enter on whatever prompt is on screen" (that is an option you turn on, not what it does by default). Each is now what can be checked today.
- **"Does it spend usage credits?" said "No."** The resume is a message, and it uses your plan like any message you type. It still doesn't change your plan, limits or credits.
- **"Rewake has no background service"** is now "no always-on service", and says that on Linux without systemd or `at` (WSL, containers) Rewake runs its own process while a resume is waiting.
- **The website said "Early release (0.2)" while npm served 0.3.0.** The landing page now takes the version from `package.json`, and a test fails when the README or the docs fall behind.
- **A scheduled message is no longer readable by every other process on your computer.** When Rewake continued a closed session, it passed your message to the agent as a command-line argument, and a command line is public: any other program (or another user) on the machine could read it from the process list for as long as the run lasted. Rewake now hands the message to **Copilot CLI** and **Gemini CLI** on their standard input, and to **Grok Build** (whose CLI reads no prompt from standard input) in a file only you can read, deleted the moment the run ends. The **Antigravity CLI** preview still passes it as an argument: its CLI documents no other way to take a prompt, and Rewake won't guess a flag; it's noted in the docs and will be fixed once `agy` can be checked. Nothing left your computer either way.
- **Rewake's own writes into your files can't be redirected.** `install` wrote its temporary file at a predictable name without demanding to create it, and the login item was written in place. Something that could plant a symlink at that name first (anything running as you, or another user where the folder allows it) could have turned an install into a write of Rewake's choosing somewhere else — including the macOS login item, which runs at sign-in. Both now create their temporary file exclusively, under a random name, and replace the file itself rather than following a link standing there. Backups and file permissions are unchanged.

## [0.3.0] - 2026-10-08

### Added

- **Cursor's own agent (preview):** `agent-rewake install --only cursor` adds two hooks to `~/.cursor/hooks.json` (yours stay). When a chat stops at its usage limit, Rewake tells you to run `agent-rewake continue` and choose when (Cursor doesn't say when its limit resets); at that time (within 4 hours of the limit) it sends "Resume the work from where you were interrupted." (marked as from Agent Rewake) into the same chat, while that Cursor window stays open; typing in the chat meanwhile cancels it. If the window was closed or reloaded, a notification says to continue it yourself. A limit that waiting won't lift (a free plan's allowance, or one that needs payment) gets a notification instead. Continuing the same chat was tried in Cursor 3.23; a real Cursor usage limit wasn't yet.
- **Linux without systemd or `at` (WSL, containers) can continue sessions too:** before, planned resumes there waited until you next opened an agent. Rewake now uses its own background process, one for all planned resumes, which ends when none is left. It stops when you log out or restart, and starts again the next time you use an agent. `agent-rewake install` and `doctor` say when it's used, with the fix: systemd in WSL, or the `at` service elsewhere.

### Changed

- The landing page's comparison leads with what Rewake covers and says where each other way stops (one agent only, no scheduling, keystrokes into a pane, a dropped time zone, a prompt approved for you). It no longer links to them.
- **Claude Code's continues show up in `agent-rewake doctor`:** its planned continues count with the other agents' ("keep Claude Code open"), and a session waiting for your answer is named, with its folder. Rewake's plugin now records each session's folder with its limit (never message text).
- **Claude Code follows Rewake's setting for every agent:** after `agent-rewake continue --always` (or turning it on in Zed's Settings), Claude Code continues without asking too, and `/rewake auto` says why. `/rewake auto off` in Claude Code keeps asking there, whatever the shared setting.
- **The README, docs and website start from where you work**: a terminal, Claude Code's panel in VS Code or Cursor, Zed, JetBrains IDEs and Devin Desktop, each with what Rewake does there and its status. Zed's menu, forms and settings have their own section, and the website's "How it works" and agent tiles put the terminal agents first. The status badge says v0.2.
- **The README, docs and website say what's been tried for each preview, and what hasn't:** Claude Code in a terminal, VS Code and Cursor, Copilot CLI, Gemini CLI and Grok Build were tried by hand on a Mac with a test usage limit (none has met a real one yet); Codex only in automated tests; Antigravity CLI not yet. The docs also explain that a closed session is continued without your shell profile's settings, that Copilot's and Grok's limits don't say when they reset (so `continue` asks you when), and how Gemini CLI shows Rewake's answer to `/rewake`.

### Fixed

- **Claude Code's `/rewake` questions in VS Code and Cursor:** "What should Rewake send…" offers "Continue from where you left off." and "Check where things stand and report back.", or type your own; before, the panels showed Yes/No, and "Yes" would have been sent as the message. The custom-time question offers examples with their times, and a time typed in the first question is used.
- **Times without brackets inside brackets:** "12:07 AM tomorrow, Thursday" instead of "12:07 AM tomorrow (Thursday)", so labels read "In 1 hour (12:07 AM tomorrow, Thursday)". A change an agent proposes in Zed lists its parts with semicolons.
- **Gemini CLI shows "[Agent Rewake]"** after Rewake's message, not an internal hook name.
- The website's schedules-page demo shows Rewake's real version again.

- `agent-rewake install` / `uninstall`: puts Rewake in front of the agents you already use, under their own names, with backups and comments kept; `doctor` checks the setup.
- Works with Claude Agent, Codex, Gemini CLI, GitHub Copilot, OpenCode, goose and every other external agent Zed runs, npm-based or binary, plus custom agents.
- macOS, Linux (including Flatpak Zed) and Windows.
